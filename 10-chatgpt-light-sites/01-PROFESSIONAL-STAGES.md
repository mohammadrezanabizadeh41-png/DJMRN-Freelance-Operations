## هدف، دامنه و حداقل محصول
ساخت و آزمایش نمونه‌های سبک ولی حرفه‌ای توسط ChatGPT GPT-6 با MCP متصل Bridgerator و ابزارهای توسعه لپ‌تاپ، مستقل از Codex و پروژه سنگین سه‌بعدی. هر نمونه **یک پروژه و پوشه محلی مجزا**، خروجی قابل اجرا، تست قابل تکرار، و Git branch/commit مختص خودش خواهد داشت. هیچ سایت عمومی یا پرداخت واقعی بدون تأیید جداگانه.

### خانواده‌های سایت / انتخاب فقط یک مسیر در هر پایلوت
| شناسه | نوع پروژه | مسیر پیشنهادی | مرز و شرط انتخاب |
|---|---|---|---|
| A | تک‌صفحه/شرکتی/خدماتی/نمونه‌کار | HTML + CSS + JS؛ Vite فقط اگر build لازم شد | پیش‌فرض، کمترین پیچیدگی و RAM |
| B | سایت چندصفحه‌ای، بلاگ، مستندات، چندزبان | Astro + CSS / محتوای Markdown | وقتی صفحه و SEO و ساختار محتوایی زیاد شد |

| D | فروشگاه آزمایشی (بدون پرداخت واقعی) | A/B + داده ساختگی + سبد/سفارش/رسید آزمایشی | کوچک‌ترین آزمایش انتهابه‌انتها؛ بدون سرور مالی |
| E | فروشگاه واقعی وردپرسی | WordPress + WooCommerce + DB سازگار، پرداخت فقط بعد از تأیید جدا | اجرا/انتشار واقعی مشروط؛ Playground compatibility کافی فرض نشود |
| F | وب‌اپ با کاربران واقعی، داده پایدار، پنل | ابتدا تست نیاز؛ سپس Hono/PocketBase یا راه‌حل مناسب | فقط پس از اثبات نیاز به backend/auth/state؛ نه در پایلوت ۱ |

**Decision tree:** اگر محتوا ثابت و فرم نمایشی کافی است → A. اگر صفحات زیاد و جست‌وجو/ترجمه مهم است → B. اگر خود مالک باید از پیشخوان ویرایش کند → C. اگر فروش آزمایشی می‌خواهیم → D روی A. اگر سفارش و پرداخت واقعی می‌خواهیم → E و مجوز/امنیت مستقل. اگر داده چندکاربره و workflow سمت سرور واقعی می‌خواهیم → F. مسیرها موازی نصب نمی‌شوند.

### S03 — پژوهش الگوهای حرفه‌ای Responsive UX برای نمونه 01 / M01 (2026-11-22)
**وضعیت:** `RESEARCH_SYNTHESIS_DONE / P02_PARTIAL / NOT_BUILT`؛ S03 یک فعالیت پژوهشیِ تعیین‌شده توسط مالک است و زیر P02 ثبت می‌شود؛ شمارهٔ P00–P12 یا شناسهٔ مدل 01–22 تغییر نمی‌کند.

- **نمونهٔ دقیق:** `M01` = سایت تک‌صفحه‌ای خدمات/نمونه‌کار با HTML+CSS+JavaScript خالص؛ با `M02` = فروشگاه آزمایشی مبتنی بر Vite متفاوت است. وضعیت پیشنهاد قدیمی پایلوت M02 بدون تغییر می‌ماند.
- **مراجع طراحی برای بررسی/الهام:** [Instrument](https://www.instrument.com/) (خدمات→نمونه‌کار→تماس)، [Pentagram Work](https://www.pentagram.com/work/) (گالری و دسته‌بندی)، [Linear](https://linear.app/) (وضوح پیام و سلسله‌مراتب)، [Hello Monday](https://www.hellomonday.com/) (هویت بصری و تعامل محدود)، [Studio Lenzing](https://www.studiolenzing.com/) (توضیح خدمات و CTA). این‌ها نامزدهای الهام و تحلیل کیفی‌اند، **نه اثبات سنجش عملکرد یا مجوز استفاده از دارایی‌ها**.
- **الگوهای استخراج‌شده:** هدر ساده Services/Work/About/Contact، معرفی کوتاه و دو CTA «دیدن کارها»/«تماس»، کارت خدمات و نمونه‌های واقعی، توضیح فرایند و راه ارتباطی معتبر؛ پرهیز از نمایش نمونه/مشتری ساختگی، WebGL اجباری، ویدئوی خودکار و ناوبری پنهانِ غیرضروری. پیشنهاد بصری پژوهش: A Editorial + C Technical، با مقدار کمی B Interactive؛ **هنوز مصوب نیست**.
- **سه اندازه، فرضیه برای طراحی و تست آینده:** موبایل `320–599` یک ستون/CTA آشکار؛ تبلت `600–1023` دو ستون کارت؛ دسکتاپ `>=1024` معرفی دو ستونی/گالری سه ستونی. Breakpoint با محتوا تعیین شود. آزمون‌های هدف: 320، 360، 390، 768، 1024، 1440، 1920 CSS px؛ چرخش، zoom، keyboard و RTL در صورت نیاز.
- **معیارهای طراحی و QA بعدی:** دسترس‌پذیری هدف WCAG 2.2 AA؛ فوکوس واضح، متن جایگزین، لمس مناسب، `prefers-reduced-motion` و عدم overflow؛ اهداف عملکرد LCP≤2.5s / INP≤200ms / CLS≤0.1 **اندازه‌گیری نشده‌اند**. [MDN Responsive Design](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design)، [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)، [Web Vitals](https://web.dev/articles/defining-core-web-vitals-thresholds).
- **موارد باز:** آزمون زندهٔ مستقل مرجع‌ها روی سه viewport، حقوق تجاری تصویر/فونت/آیکن، brief و انتخاب بصری مالک، طرح تأییدشده، کد سایت، تست مرورگر و انتشار. **S03 فقط پژوهش و استخراج الگو انجام شده؛ P02 به‌طور کامل PASS نشده و M01 همچنان [ ] است.**
- **قانون ثبت مراحل آینده (درخواست مالک 2026-11-22):** پس از اجرای هر مرحلهٔ مجاز، نتیجهٔ واقعی/محدودیت/شواهد در **همین نقشهٔ راه** ثبت و وضعیت مدل مربوط در **همین کارتابل 22 نمونه** به‌روزرسانی شود؛ فقط در `project/chatgpt-light-sites-20261121/10-chatgpt-light-sites/`، بدون تغییر `main`، پروژهٔ 09 یا تیک زدن ساختِ آزمون‌نشده.

### «Done» واقعی برای هر نمونه
- URL محلی باز شود؛ رفتار یک سناریوی کامل از کلیک تا نتیجه در Browser بررسی شود.

- keyboard navigation، متن فارسی و RTL (اگر فعال است)، reduced motion و دسترس‌پذیری به‌صورت دستی هم بررسی شوند؛ automated axe به‌تنهایی کافی نیست.
- هیچ credential، داده مشتری، شماره کارت، پرداخت واقعی و API پولی در نمونه وجود نداشته باشد.

## مسیرهای ابزار بر حسب مرحله

- **P08 مسیر E:** WooCommerce + دیتابیس سازگار و آزمون تراکنش‌های تستی؛ نه در نمونه سبک پیش‌فرض.
- **P09:** اول Node tests و ابزار مرورگر موجود؛ سپس Vitest/Playwright/axe؛ Lighthouse فقط در gate عملکرد.
- **P10:** MCP تخصصی فقط اگر خود Bridgerator/CLI محدودیت اثبات‌شده داشته باشد؛ هر MCP جدید نیازمند client bridge و approval است.

## آزمایش نخست پیشنهادی
**PILOT-01: فروشگاه نمونه ۶ محصولی بدون پرداخت واقعی (مسیر D روی A).**
۱) داده JSON کالا با قیمت واحد دقیق؛ ۲) موبایل/دسکتاپ؛ ۳) جست‌وجو/فیلتر؛ ۴) سبد خرید، افزایش/کاهش و صفر شدن سبد؛ ۵) جمع مبلغ و رسید DEMO؛ ۶) حالت‌های خطا، reload و reset؛ ۷) تست سناریو و دسترس‌پذیری. ابتدا فقط صفحه محصول→سبد→رسید، سپس فیلتر/ظاهر؛ هیچ دیتابیس یا auth لازم نیست. برند/دسته محصول هنوز انتخاب نشده و هر نمونه فقط پس از تأیید کاربر ساخته می‌شود.

## RAM، امنیت و توقف
- لپ‌تاپ ۸GB RAM؛ در هر زمان یک browser سنگین یا host تست؛ Docker/WordPress/Woo فقط اگر لازم شد. آستانه اضطراری سابق مالک ۱۰۰MiB free؛ در pilot، قبل از رسیدن به این حد memory را بررسی و اجرای سنگین را محدود کنید، بدون حذف داده یا خاموش‌کردن VPN.
- GitHub public است؛ هیچ .env، credential، کوکی، پروفایل مرورگر، محتوای خصوصی آرشیو وب، کد vendor یا دارایی دارای حقوق نامشخص در GitHub منتشر نشود.
- هر نصب، MCP خارجی، OAuth، هزینه، overage، دامنه، انتشار، پرداخت واقعی، merge یا تغییر امنیتی منوط به پیشنهاد اثر + تأیید صریح همان نوبت است.
- اگر بدون افزودن چند سرویس و agent، MVP واقعی ساخته نمی‌شود، scope را کوچک کنید. ابزارهای تحقیق‌شده به معنی نصب/فعال‌سازی نیستند.
