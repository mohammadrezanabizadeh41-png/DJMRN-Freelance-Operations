# Awarded-job workflow — practical delivery memory

Create `05-client-projects/JOB-YYYY-NNN/` **only** when genuine award/agreement evidence is available and the user decides to carry out the work. Name/file does not imply contractual status.

Minimal first record: `README.md` from [JOB template](../templates/JOB.md), a safe link to `OPP`, scope, acceptance criteria, due date, deliverables reference, dependencies and milestones.

During work append dated progress (what changed, commands/inputs/outputs, approved software/version, meaningful tests, mistakes/recovery), then validate delivery, customer acceptance and payment evidence separately.

Use existing `06-tooling/TOOL-REGISTRY.md` for tools deployed; short links avoid duplicating installations across jobs. Document lessons in `07-lessons-and-playbooks/` after observed results.

No client-protected assets, correspondence, passwords, personal finance or NDA content. Avoid placing actual delivered customer source in this operational memory unless contract explicitly permits and user authorizes.
