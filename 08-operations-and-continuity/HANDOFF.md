# Protocol for a new assistant — READ FIRST

۱. همین مخزن: `README.md` → `PROJECT-RULES.md` → `08-operations-and-continuity/CURRENT-STATUS.md` → `08-operations-and-continuity/ACTIVITY-LOG.md`.
۲. سپس پروندهٔ سایت انتخابی (`01-platforms`) و فرصت (`04-opportunities`) و سفارش (`05-client-projects`) و ابزارها (`06-tooling`) را بخوان.
۳. تفاوت snapshot تاریخی با CURRENT و Evidence/Assumption/Proposal را مشخص کن؛ حساب، قوانین پرداخت و KYC بدون شاهد جدید فکت نیست.
۴. برای اطلاعات معنادار جدید: فقط CURRENT مربوط به همان بخش را با شاهد به‌روز کن، رخداد را append کن، commit و blob را بازخوانی کن؛ اگر دسترسی نوشتن نداری متن دقیق patch تحویل بده.
۵. برای تصمیم معماری/سیاست حاکمیتی Notion canonical را بخوان؛ برای research ابزار کتابخانه Applied را بررسی کن. GitHub منبع شواهد/تاریخچه عملی همین مأموریت است.
۶. فقط پروژهٔ واقعاً درخواست‌شده را پیش ببر؛ ایدهٔ آینده مجوز ساخت agent/automation/API/DB نیست.
۷. هر نامه/پیشنهاد/ثبت‌نام/پرداخت/اطلاعات خصوصی مشتری صرفاً با تأیید صریح کاربر و رعایت قوانین پلتفرم.
۸. هرگاه خطای اتصال یا عدم دسترسی رخ داد، status=UNVERIFIED و دست از حدس‌زدن/ثبت موفقیت بردار.
