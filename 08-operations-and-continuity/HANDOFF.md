# Session handoff — operational resume protocol

## Quick read order
1. `README.md`, `PROJECT-RULES.md`.
2. `08-operations-and-continuity/CURRENT-STATUS.md`, then `WORK-INDEX.md`.
3. Only the selected platform/OPP/JOB and relevant lesson; read `ACTIVITY-LOG.md` when the latest action or disputed status matters.
4. `ARCHITECTURE.md` and `DR-####` only for major method change.

## Assistant handoff contract
Reply to the next assistant with: `Current goal`; `primary record file`; `observed latest state and date`; `last completed action`; `open blockers`; `pending human approval`; `next smallest safe action`; `evidence/permalink`; `verified commit`.

## Recording a real operation
- Choose one existing canonical site/account/lead/job file; create new record only if missing and genuinely observed.
- Assign stable ID from templates. Avoid duplicates by original listing URL, client-safe job ID and platform identity.
- Record only safe and necessary facts; differentiate direct evidence, historical notes, user report and unknown.
- Before sending/submitting/buying/publishing etc, require exact action-specific approval.
- Update the primary record, append concise event entry, update `CURRENT-STATUS.md` if the user’s next step changes, maintain navigational links in `WORK-INDEX.md`.
- Git commit, read files and branch back; if access/error is unclear, say `UNVERIFIED` and do not claim success.

## Scope and status
The GitHub repo is **the freelance project authority**. Historical Notion/Drive references may be useful to explain past research; they are not mandatory or current. Do not mutate them. Other DJMRN repositories are separate.

## Failure / privacy
No source access → explain partial coverage; don't reconstruct decisions from guesses. No income/contract until confirmed. Never write passwords, identity documents, private customer correspondence, billing details or protected deliverables. Git is not a secure personal-data vault.
