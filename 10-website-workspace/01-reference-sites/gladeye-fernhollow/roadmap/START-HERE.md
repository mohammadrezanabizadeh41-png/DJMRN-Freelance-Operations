# شروع نشست اجرای Fernhollow

**اولین سفارش آماده برای صدور، CODE-01 در P0 است.** مجوز فعلی متعلق به نگارش و انتشار اسناد است. برای آغاز کار کدنویسی، مالک می‌تواند سفارش زیر را در همین پرونده صادر کند.

> P0 / CODE-01 را اجرا کن. در پوشهٔ خصوصی کاری برای این مرحله، checker آفلاین ورودی‌ها را با ابزار موجود بساز، روی metadata و فایل‌های فقط‌خواندنی امتحان کن، کنترل‌های منفی را با دادهٔ خودساخته اجرا کن و manifest و رسیدهای P0 را تحویل بده. دامنهٔ این سفارش کنترل ورودی و ثبت تصمیم حقوق است.

1. از [نقشه‌راه](ROADMAP.md) فقط P0 و قرارداد receipt را بخوانید. با [SOURCE-ROUTES](SOURCE-ROUTES.md) مسیرهای OWNER، INDEX، F17 و A10 را از پروفایل محلی حل کنید.
2. با [کاربرگ P0](WORKSTREAMS/01-source-versions-rights.md) خانوادهٔ تعیین‌شده و نتیجهٔ static diff هشت filename را کنترل کنید. نسخه‌های مبهم جدا بمانند. ۴۳ قطعه با شناسه و متن اصلی در X44 حفظ می‌شوند.
3. در [جدول گیت‌ها](GATE-CROSSWALK.csv) ردیف‌های G00، G01 و G02 را باز کنید. قبل از نوشتن، مجوز scope و مسیر W را مشخص کنید؛ هزینهٔ افزوده باید مشخص و صفر باشد.
4. دفتر تحویل P0 شامل `inputs.lock.json` با ۱۷+۱۰ هویت و مسیر، checker، نتایج مثبت و منفی، وضعیت حقوق و رسیدهای `QA/receipts/G00.json` تا `G02.json` است. شناسهٔ gate و actual result را در فایل ثبت کنید. اگر خواندن شکست خورد، همان فایل/هش/خطا و کوچک‌ترین اقدام لازم را ثبت کنید.
5. سفارش بعدی CODE-02 در [قرارداد boot](WORKSTREAMS/02-runtime-boot.md) است. پیش‌شرط آن lock معتبر و مجوز تحلیل ایستا است. برای آزمایش واقعی Webpack، تصمیم مستند دربارهٔ حقوق استفادهٔ خصوصی، اجازهٔ اجرا و محیط محلی جداگانه لازم است.

برای ادامهٔ یک run قبلی از آخرین receipt معتبر و hash ورودی آن شروع کنید. تغییر خانواده، hash یا دستگاه نتیجهٔ run قبلی را فقط به همان شرایط قبلی محدود می‌کند. وضعیت جاری اجرای ۴۶ گیت هنگام تنظیم برنامه `NOT_EXECUTED` است.
